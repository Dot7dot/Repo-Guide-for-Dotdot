專案簡介

每一關會有一位隨機組成的虛構客人坐到吧台前，你要在限定的訊息次數內，從閒聊的線索猜出對方的職業。客人由瀏覽器內的小型語言模型扮演，不會直接說出職稱，也不能直接問職業。通過的關卡越多，可用的訊息次數越少。

使用技術

WebLLM / WebGPU
在瀏覽器執行 Qwen2.5 小模型，扮演客人並協助判定猜測。
JavaScript
以原生 ES Modules 實作回合流程、規則判定和提示詞組裝。
JSON 角色資料
隨機組合職業、個人資訊、特質與經歷四份各自獨立的資料。
GitHub Actions
推送到 main 後自動部署到 GitHub Pages。

架構概覽

回合規則和猜測判定由確定性程式處理，模型只負責以角色口吻回覆。規則書轉成精簡提示詞，與壓縮過的人物資料一起送給模型。網址加上測試參數可改用假模型，不必下載模型。

  1. 隨機抽出客人
  2. 送出閒聊訊息
  3. 規則檢查與模型回覆
  4. 判定猜測並計次

詳細架構

  • 角色資料與提示詞

    從四個資料夾各抽一份 JSON 組成客人，再依字數預算壓縮成人物區塊。規則書的精簡版與人物資料一起組成系統提示詞。

  • 規則與猜測判定

    規則層計算每關次數、偵測直接問職業，並以兩道關卡先抽出猜測的職稱，再與答案比對。接近的猜測才交給模型確認，模型無法把不相關的猜測判為答對。

    • js/rules.js↗
    • tests/rules.test.mjs↗
    • tests/judge.test.mjs↗

  • 本機模型與遊戲流程

    載入器檢查 WebGPU 並依裝置選擇模型，限制單次只生成一段並裁剪過長的對話。遊戲主程式管理關卡、存檔還原與裝置遺失後的重新載入。

未來擴充構想

  • 職業難度分級

    依職業的常見程度或線索明顯度調整關卡，讓高關卡出現更冷門的職業。

  • 提示額度

    用剩餘次數換取一則額外線索，在安全度與挑戰間讓玩家取捨。

  • 對話回顧卡

    結算時整理客人透露的線索與猜錯的職業，方便分享或重玩。
